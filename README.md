# KSA 자기소개서 Evidence Map

한국과학영재학교 3차 면접 대비용 개인 학습 도구.
자기소개서 문장에서 **근거 → 위험 표현 → 예상 질문 → 답변 구조**로 이동한다.
포트폴리오가 아니라 면접 전날까지 반복해서 쓰는 도구다.

## 무엇을 하는가

- 자기소개서 6문항을 원문 그대로 읽는다.
- 면접관이 파고들 만한 표현만 하이라이트되어 있다. 누르면 오른쪽에 상세가 열린다.
- 각 근거에는 **PANEL / PREP**(면접관이 볼 수 있는 자료인가)과
  **MEASURED / INFERRED / UNKNOWN**(확인 수준)이 붙어 있다.
- 위험 표현은 "이렇게 말한다"까지 함께 제시한다.
- 예상 질문에는 **왜 이 질문이 나오는지**가 반드시 붙어 있다.

## 네 가지 화면

| 화면 | 용도 |
| --- | --- |
| 전체 지도 | 6문항을 한눈에. 문항별 위험 수, PANEL/PREP 근거 구성, 질문 수 |
| 자소서 | 줄 노트 위의 원문을 읽으며 표현별 근거·그림·위험·질문 확인 |
| 질문 은행 | 예상 질문 62개. 답변은 접혀 있고 눌러야 펼쳐진다(연습용) |
| 위험 표현 | 정정해야 할 표현 40건(위험 15 · 주의 25)만 모아 보기 |

상세 패널은 **근거 / 그림으로 / 위험 / 질문 / 답변** 탭으로 나뉜다.

## 그림으로 이해하기

말로 설명하기 어려운 것은 전부 그림으로 만들었다. 대부분 직접 눌러 볼 수 있다.

| 시각화 | 무엇을 보여주나 |
| --- | --- |
| **파노 평면** | 직선 두 개를 고르면 교점이 정확히 하나임을 직접 확인 |
| **도블 → 사영평면 번역표** | "카드=직선, 그림=점" 대응 |
| **나비 정리** | 실제 좌표로 그린 도형. MX = MY = 44.8 |
| **이분 매칭 증가 경로** | 7단계로 재생. 좌석이 찼을 때 밀어내는 과정 |
| **'최적'은 무엇인가** | 코드가 최대화하는 것 vs 자소서 표현이 암시하는 것 |
| **측정 결과 차트** | 실제 평균 · 측정 범위 · "V자형" 주장 겹쳐 보기 |
| **실험 장치도** | 빗면 28.4cm/90cm, Δx의 정확한 정의 |
| **관절각 계산** | 슬라이더로 팔을 움직이며 20° 판정 체험 |
| **커밋 타임라인** | 두 프로젝트의 시점 차이와 제출일 미상 구간 |
| **진로 타임라인** | 1학년 → 2학년 → 자소서로 이어지는 진로 희망 |

이분 매칭 예시 데이터는 `arrange.py` 끝 주석에 실제로 적혀 있는 값을 그대로 쓴다.

우상단 **INTERVIEWER VIEW / PREP LAB** 전환:

- `INTERVIEWER VIEW` — 면접관이 실제로 볼 수 있는 자료(자소서·생기부)만 남긴다.
  "이 근거만 가지고 답할 수 있나"를 점검할 때 쓴다.
- `PREP LAB` — GitHub·탐구보고서·이론·본인 설명까지 전부 본다.

## 데이터가 곧 내용이다

UI 코드에는 내용이 없다. 전부 `src/data/` 아래에 있다.

```
src/
  types.ts                 데이터 모델 (SourceKind, Visibility, Certainty, Risk …)
  data/
    essay.ts               자기소개서 원문 (PDF 전사, 문장 단위)
    hotspots.ts            하이라이트할 표현과 우선순위
    evidence.ts            검증된 근거 인덱스 (출처·인용·해석 분리)
    details.q1q3.ts        Q1~Q3 상세 (근거·위험·질문·답변 구조)
    details.q4q6.ts        Q4~Q6 상세
    index.ts               인덱스 + 무결성 검증
  components/              Overview, EssayReader, DetailPanel, QuestionBank, RedFlagView
  visuals/                 시각화 10종 + 레지스트리(index.tsx)
  hooks/useLocalStorage.ts 학습 상태 저장
  styles.css               라이트/다크, 모바일 bottom sheet
```

### 무결성 검증

`validateData()`가 앱 시작 시 돌면서 다음을 확인한다.

- **모든 `hotspot.exactText`가 자소서 원문 문장 안에 그대로 존재하는가** ← 가장 중요
- hotspot ↔ detail ↔ evidence 참조가 모두 유효한가

하나라도 깨지면 화면 상단에 빨간 경고가 뜬다.
경고가 떴다면 원문을 건드렸거나 하이라이트 지정이 잘못된 것이다.

## 내용 작성 규칙

이 저장소에 내용을 추가할 때 지킨 규칙이다.

1. **자기소개서 문장은 고치지 않는다.** 맞춤법도 띄어쓰기도 원문 그대로 둔다.
2. **인용과 해석을 섞지 않는다.** `excerpt`는 원문, `interpretation`은 해석이다.
3. **확인하지 못한 것은 UNKNOWN으로 표시한다.** 그럴듯한 추측으로 채우지 않는다.
4. **본인 작업과 협업자 작업을 합치지 않는다.**
5. **예상 질문은 PANEL 자료(자소서·생기부)에서 출발한다.** GitHub에만 있는 내용을
   면접관이 먼저 물어보는 것처럼 만들지 않는다.
6. **저장소에 지금 있다고 지원서 당시에도 있었다고 하지 않는다.** commit 날짜로 확인한다.
7. **약점을 감추지 않는다.** 대신 "어떻게 고쳐 말할지"까지 붙인다.

## 디자인

- 색은 한국과학영재학교 브랜드 네이비 **#0B266B**를 기준으로 잡았다(학교 공식 사이트에서 확인).
- 글꼴은 **Pretendard Variable**. 한국어 가독성이 최우선이라 본문 17px / 줄간격 34px로 넉넉히 두었다.
- 자소서 본문은 줄 그어진 노트 위에 얹었다. 줄 간격과 `line-height`가 정확히 같은 값(`--lh`)이라
  글자가 항상 줄 위에 앉는다.
- 색만으로 의미를 전달하지 않는다. 모든 배지에 라벨과 기호가 함께 붙는다.

## 개인정보
